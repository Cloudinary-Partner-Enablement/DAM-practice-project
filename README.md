# Meadowlane DAM practice project

In this project you set up Cloudinary's Digital Asset Management (DAM) for a customer, the way you would in a real implementation. You organize a product library, add structured metadata, automate uploads with a preset, and prepare a campaign for an outside agency. An optional bonus task has you search the library with the Search API.

You work in your partner demo account. When you finish the steps, a Node.js check script confirms that what you built is in place. You then submit the script's results file.

**Time:** about 48 minutes (42 minutes of steps plus about 6 to run the check and submit), plus about 4 for the optional bonus task.

**You will need:** your partner demo account and its API credentials (the `CLOUDINARY_URL`), Node.js 18 or later, and the project files in this repository.

**Skills practiced:** folder structure, structured metadata, upload presets, bulk upload, tagging, collections and sharing, roles, and the Search API.

## Scenario

Meadowlane is an ecommerce retailer that sells outdoor gear and home goods. Its product photos are scattered in a shared drive with inconsistent names, so merchandisers waste time finding the right image. Meadowlane has just signed up for Cloudinary and has asked your team to get its media library ready before the Fall Sale.

Meadowlane's requirements:

1. Product photos are organized into **Outdoor** and **Home** folders under a **Products** folder, and the Fall Sale banner has its own folder under **Campaigns**.
2. Every product photo records its **SKU**, **Category** (required), and, for sale items, a **Usage end date** after which the image should no longer be used.
3. New outdoor photos are tagged and filed automatically when they are uploaded.
4. An outside agency will build the Fall Sale pages. It should see only the Fall Sale products and banner, and it should not be able to change anything.
5. Merchandisers need to find Fall Sale outdoor products that are still in use, using a saved search expression (optional bonus task).

## Running the check script

Run `node check.js` from the project folder. It uses the `CLOUDINARY_URL` in your environment and prints each step as pass or fail with a short explanation of anything missing. Run it as often as you like. Search results can take a few seconds to catch up after an upload, so the script retries a few times before it marks a step as failed.

The script only reads from your account and never changes it. It never prints your API secret. If the script can't connect, check that `CLOUDINARY_URL` is set in the same terminal.

Requires Node 18 or later. Results are written to `results.json`.

If `search-expression.txt` still has only its note lines, the check skips step 9 and does not count it.
